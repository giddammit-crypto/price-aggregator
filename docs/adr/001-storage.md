# ADR 001: Хранение данных в файлах (NDJSON + PHP-индексы OPcache)

- **Статус:** Принято (Accepted)
- **Дата:** 03.10.2026
- **Контекст:** Обычный виртуальный хостинг без MySQL/СУБД, без демонов.

## Решение

1. **Каталог товаров и позиции:**
   - Позиции магазинов хранятся в шардированных NDJSON-файлах: `data/items/{shop}/s{00-ff}.ndjson`. Шардирование: `crc32(external_id) % 256`.
   - Товары хранятся в паках `data/catalog/products/p{000-255}.ndjson` (шард = `product_id % 256`).
   - К каждому паку строится PHP-индекс смещений `p{000-255}.idx.php` (`return [id => [offset, len], ...];`). Чтение товара происходит за O(1) через `fseek()` и `fread()`.

2. **Снимки каталога (Snapshots для веба):**
   - Сайт читает данные только из активного неизменяемого снимка: `data/snapshots/{snapshot_id}/`.
   - Активный снимок определяется атомарно через указатель `data/snapshots/CURRENT`.
   - Данные для листингов и поиска компилируются в нативные PHP-файлы (`return [...];`), которые OPcache держит в оперативной памяти с нулевыми затратами на парсинг.
   - Фильтрация листинга (категории до 20-30 тыс. строк) выполняется в PHP одним циклом за 10–30 мс.

3. **Запись данных:**
   - Веб-процессы никогда не пишут в каталог и индексы.
   - Веб делает только append в лог-файлы (`logs/clicks/`, `subs/`, `logs/reports/`) с использованием `flock(LOCK_EX)`.
   - Пересборку каталога и публикацию снимков выполняет исключительно фоновый процесс `cron/run.php` с эксклюзивным `flock` на файл блокировки задачи.
   - Любая замена файлов каталога выполняется через временный файл в той же файловой системе и атомарный вызов `rename()`.

## Последствия

- **Плюсы:** Полная автономность от сторонних СУБД, устойчивость к сбоям, нулевые блокировки читателей, мгновенное переключение снимков каталога, нулевой риск порчи каталога веб-запросами.
- **Минусы / Ограничения:** Потолок масштабирования до ~100 000 товаров на файловом диске. При превышении требуется миграция на СУБД; архитектура изолирует доступ через интерфейсы `ProductRepositoryInterface`, `CatalogIndexInterface`, что позволит заменить реализацию без изменения контроллеров.
